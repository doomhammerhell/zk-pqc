\begin{abstract}
Smart contract ecosystems remain structurally dependent on elliptic-curve signatures for state authorization, a dependency that becomes brittle under a realistic long-horizon adversary with eventual quantum capability. This paper specifies a research-grade framework for post-quantum authorization in STARK-based execution environments, with a primary focus on deterministic smart contract languages such as Cairo. Our design is intentionally hash-centric: it treats conservative symmetric assumptions (collision and preimage resistance) as the stable substrate for archival security, and then engineers a modular verification stack composed of hash abstractions, Merkle commitment systems, hash-based signatures (OTS/WOTS+/XMSS-family), and proof-system alignment through arithmetization.
We provide a formal semantic model of authorization as guarded transitions, compositional security arguments, and a roadmap toward proof-carrying transactions and recursive verification. Appendices include a Coq-oriented specification skeleton, HyperLTL formulations of authorization hyperproperties, and an AIR-level (Algebraic Intermediate Representation) specification outline for STARK arithmetization. The result is a cryptographic infrastructure layer intended to be auditable, reproducible, and extensible as a long-term research and engineering program.
\end{abstract}

Post-Quantum Cryptography, STARK, Cairo, Hash-Based Signatures, Merkle Trees, Formal Semantics, Hyperproperties, AIR, Proof-Carrying Authorization
\end{IEEEkeywords}

\section{Introduction}
Blockchains hard-code time asymmetry: state is permanent, while cryptographic assumptions are not. A system that is ``secure under current assumptions'' is insufficient when ledger state must remain enforceable decades later. Contemporary authorization flows typically rely on ECDSA/EdDSA; yet Shor-type quantum adversaries can collapse discrete-log hardness in polynomial time. Even if large-scale quantum machines are delayed, the attack \emph{store now, forge later} is rational: an adversary records signatures today and attempts key recovery or forgery later.

In parallel, the ZK ecosystem increasingly shifts execution into proof systems. STARK-based rollups and proof-verified smart contract environments require that security-critical logic be arithmetizable, deterministic, and bounded. Unfortunately, most NIST-standardized PQC signature schemes (notably lattice constructions) are computationally hostile to STARK-friendly execution constraints: they rely on large polynomial arithmetic, sampling, and heavy integer operations.

This paper takes a different foundation: post-quantum authorization for STARK-based contracts should begin with hash-based constructions. Hash-based signatures align with proof systems because their core operations are hash evaluations and simple combinators. We then elevate this baseline into a long-horizon, modular infrastructure that supports: (i) succinct public key commitments (Merkle roots), (ii) deterministic on-chain verification, (iii) proof-carrying authorization as a scaling primitive, and (iv) formal semantics and hyperproperty-level constraints to prevent cross-trace failures such as replay, equivocation, or accidental key reuse.

\subsection*{Contributions}
\begin{itemize}
\item We define a modular architecture for post-quantum authorization in Cairo/STARK environments: hash layer, Merkle layer, signature layer, contract layer, and proof layer.
\item We provide a formal semantic model of authorization as guarded state transitions and state formal theorems for authorization soundness under explicit assumptions.
\item We propose a proof-system alignment strategy via AIR constraints, enabling verification logic to become a first-class arithmetizable component.
\item We provide specification appendices: a Coq skeleton, HyperLTL properties, an AIR outline, and category-theoretic diagrams clarifying compositional structure.
\end{itemize}

\section{Threat Model and Long-Horizon Security}
We model an adversary $\mathcal{A}_Q$ with eventual quantum capability. The adversary can observe all on-chain data at time $t_0$ and attempt to forge authorization data at time $t_1 \gg t_0$ when quantum capabilities exist. Our objective is \emph{archival authorization}: the ability to validate that a state transition was authorized even after classical asymmetric assumptions fail.

\begin{assumption}[Quantum-Aware Hash Security \& Field Width Paradox]
\label{assm:hash}
The hash function family $\Hash$ must provide at least 128 bits of post-quantum security against Grover's $\mathcal{A}_Q$. Given that Cairo's native field $\F_p$ is $\approx 251$ bits, a single-element hash is insufficient for a 256-bit classical target. We explicitly adopt a \textbf{Multi-Element State Strategy}: 
\[ \Hash_{PQ}(m) = \text{Poseidon}(m)[0] \concat \text{Poseidon}(m)[1] \]
where the internal state is expanded to ensure the preimage resistance $2^{k/2}$ remains $\geq 2^{128}$ after quadratic speedup.
\end{assumption}

\begin{remark}
This expansion doubles the AIR constraint count for every hash step but is a non-negotiable requirement for long-horizon security. We mitigate this through \emph{Arity-16 Merkle Trees}, reducing the total number of hash invocations in the execution trace.
\end{remark}

\section{System Overview: Layered Architecture}
We treat the system as an infrastructure stack rather than a single contract. The layers are:

\textbf{(L1) Hash Layer:} an abstraction over STARK-friendly hash primitives (e.g., Poseidon/Pedersen/Rescue-family), providing uniform interfaces for commitments and tree nodes.

\textbf{(L2) Merkle Layer:} generic Merkle trees with parameterized depth and hash choice, supporting inclusion proofs and root commitments.

\textbf{(L3) Signature Layer:} hash-based signature schemes (Lamport OTS, WOTS+, XMSS-like) expressed in terms of (L1) and (L2), producing signatures that are verifiable under bounded execution.

\textbf{(L4) Contract Layer:} authorization as a guard on state transitions; message binding rules; replay protection; index consumption enforcement.

\textbf{(L5) Proof Layer:} arithmetization and AIR constraints that make verification logic compatible with STARK proof generation and potentially recursive validation pipelines.

\section{Formal Model of Authorization}
We define a deterministic labeled transition system.

\begin{definition}[Transition System]
A contract execution system is a triple $(S, A, \rightarrow)$ where $S$ is a set of states, $A$ is a set of actions, and $\rightarrow \subseteq S \times A \times S$ is a transition relation.
\end{definition}

We treat each action $a \in A$ as a structured input that includes an application message $M$ and authorization data $\sigma$ (signature or proof). Let $R$ be the public commitment (e.g., Merkle root) stored in contract state or configuration.

\begin{definition}[Authorization Predicate]
\label{def:auth}
Let $\Verify(R,M,\sigma)\in\B$ be the authorization predicate. A transition $(s,a,s')$ is authorized iff $\Verify(R,M,\sigma)=\texttt{true}$.
\end{definition}

\begin{definition}[Guarded Semantics]
The transition relation is restricted by the guard:
\[
s \xrightarrow{(M,\sigma)} s' \quad \text{only if} \quad \Verify(R,M,\sigma)=\texttt{true}.
\]
\end{definition}

\subsection*{Message Binding and Domain Separation}
A central failure mode in smart contracts is signing the wrong object: inconsistent encoding, missing domain separation, or replay across domains. We define a canonical message hash:
\[
m \gets \Hash(\textsf{domain} \concat \textsf{chain\_id} \concat \textsf{contract\_addr} \concat \textsf{nonce} \concat \Hash(\textsf{calldata})).
\]
Only $m$ is fed to signature verification.

\section{Commitments and Merkle Verification}
To avoid storing large PQC public keys on-chain, public key material is committed via a Merkle root.

\begin{definition}[Merkle Commitment \& Arity Optimization]
Let leaves be $L_0,\dots,L_{N-1}$. While binary trees are depth-heavy, we utilize \textbf{Arity-$16$ (HexTrees)} to compress the path length. An inclusion proof $\pi$ for leaf $L_i$ in a depth $d$ HexTree consists of $d \times 15$ sibling nodes. In Cairo, this reduces the total recursion depth $\log_{16} N$, effectively cutting the step cost by a factor of 4 compared to binary structures.
\end{definition}

\begin{definition}[Path Verification]
$\PathVerify(R, L_i, \pi, i)=\texttt{true}$ iff the multi-branch reconstruction yields $R$.
\end{definition}

Merkle commitments are used to commit to OTS/WOTS public elements and, more generally, to commit to authorization sets (keys, roles, or policy roots).

\section{Hash-Based Signatures in STARK Environments}
Hash-based signatures are chosen for proof compatibility and long-horizon assumptions. We treat OTS-family schemes as a base layer and build composable constructions above.

\subsection{Lamport OTS (Foundation)}
Lamport OTS produces a public key consisting of hashes of secret pairs and signs by revealing one secret per message bit. This yields very simple verification (hash and compare), but signatures are large.

\subsection{WOTS+ (Compression via Chains)}
WOTS+ replaces per-bit reveals with chained hashes controlled by a Winternitz parameter. In a STARK environment, WOTS+ is attractive because the verifier performs repeated hash iterations (chain steps), which are arithmetizable and bounded.

\subsection{XMSS-like Trees (Many-Time from One-Time)}
XMSS extends OTS into a many-time scheme by placing OTS keys at leaves of a Merkle tree. On-chain state must enforce index non-reuse (or monotonicity), turning operational discipline into an explicit contract invariant.

\section{Formal Theorems: Soundness and Safety}
We state framework-level results under explicit assumptions.

\begin{theorem}[Authorization Soundness]
\label{thm:soundness}
Assume:
(i) the commitment root $R$ is correctly computed from the committed public elements,
(ii) $\PathVerify$ is sound (no false positives),
(iii) the signature verification procedure is correct relative to the committed public elements,
(iv) the contract enforces index non-reuse for OTS-family schemes.
Then no unauthorized state transition is reachable, i.e.,
\[
\forall s,s',M,\sigma,\quad \left(s \xrightarrow{(M,\sigma)} s'\right)\Rightarrow \Verify(R,M,\sigma)=\texttt{true}.
\]
\end{theorem}

\begin{proof}[Formal Reduction via Game Hopping]
We bound the advantage of a quantum adversary $\mathcal{A}_Q$ using a sequence of games:
\begin{itemize}
    \item \textbf{Game 0:} The real authorization protocol. $\mathcal{A}_Q$ wins if it produces $(M, \sigma)$ such that $\Verify(R, M, \sigma) = \texttt{true}$ for a message $M$ not signed by the owner.
    \item \textbf{Game 1:} The hash function $\Hash$ is replaced by a Random Oracle $\mathcal{RO}$. In this game, forging an inclusion proof or a signature chain requires finding a collision or a preimage in $\mathcal{RO}$.
\end{itemize}
The probability of $\mathcal{A}_Q$ winning Game 0 is bounded by its success in Game 1 plus the difficulty of distinguishing $\Hash$ from a random oracle:
\[
\Pr[\mathcal{A}_Q \text{ wins } \text{Game}_0] \leq \Pr[\text{Game}_1 \text{ success}] + \text{Adv}_{\Hash}^{\text{PRP/PRF}}(\mathcal{A}_Q)
\]
Since $\Pr[\text{Game}_1 \text{ success}]$ is strictly limited by the collision and preimage resistance of the Merkle tree and the WOTS+ chains, we have:
\[
\text{Adv}_{\text{system}}(\mathcal{A}_Q) \leq \text{Adv}_{\text{collision}}(\mathcal{A}_Q) + \text{Adv}_{\text{preimage}}(\mathcal{A}_Q) + \negl(\lambda)
\]
Under our parameterization ($R_P=83$ for Poseidon), the advantage remains $\leq 2^{-128}$, ensuring soundness.
\end{proof}

\begin{theorem}[One-Time Index Safety]
\label{thm:ots}
Assume an OTS scheme where revealing secrets for two distinct messages under the same index permits existential forgery. If the contract enforces a strict no-reuse invariant on index $idx$, then existential forgery via reuse is prevented in the on-chain execution domain.
\end{theorem}

\begin{proof}[Formal Proof via Adv Reduction]
Let $E$ be the event that an adversary $\mathcal{A}_Q$ successfully reuses an index to forge a signature. By defining $Game_{index}$ where the SMT spent-flag check is enforced, the advantage $\text{Adv}_{\mathcal{A}_Q}(E)$ is:
\[
\text{Adv}_{\text{reuse}}(\mathcal{A}_Q) = | \Pr[E \text{ in } \text{Actual}] - \Pr[E \text{ in } \text{SMT-Enforced}] |
\]
Since the JMT/SMT root transition is verified on-chain and reconstruction is guaranteed via DA State Diffs, $Game_{\text{SMT-Enforced}}$ yields $\Pr[E] = 0$. The advantage is then bounded by the probability of breaking the SMT commitment, which reduces to \textbf{Lemma~\ref{lem:merkle}}.
\end{proof}

\begin{lemma}[Merkle Inclusion Soundness]
\label{lem:merkle}
If $\Hash$ is collision resistant, then producing a proof $\pi$ such that $\PathVerify(R,L_i,\pi,i)=\texttt{true}$ for an uncommitted leaf $L_i$ is computationally infeasible up to $\negl(\lambda)$.
\end{lemma}

\begin{proof}[Proof sketch]
A successful forgery implies constructing an alternative leaf/path yielding the same root, inducing either a collision in $\Hash$ or a second-preimage in the tree compression structure.
\end{proof}

\section{AIR-Level Arithmetization Strategy}
STARK systems require expressing verification as algebraic constraints over a trace. We outline AIR constraints for: (i) hashing constraints, (ii) Merkle path constraints, (iii) chain constraints for WOTS+, and (iv) bit/field decomposition constraints for message binding. We present a structured AIR outline in Appendix~\ref{app:air}. The guiding principle is: verification logic must be expressible as a low-degree constraint system with bounded trace length. The contract implementation and the AIR specification should align so that ``verify in Cairo'' and ``verify in AIR'' are two views of the same semantic object.

\section{Category-Theoretic and Coalgebraic Structure}
Category theory is used here as a precision tool to prevent architectural entanglement. The central engineering problem in cryptographic infrastructure is interface drift: small changes in one layer silently invalidate assumptions of another layer.

\subsection{Functorial pipeline}
We model layers as morphisms:
\[
\mathsf{Secret}\xrightarrow{H}\mathsf{Hash}\xrightarrow{M}\mathsf{Tree}\xrightarrow{C}\mathsf{Root}\xrightarrow{V}\B.
\]
This pins down which invariants must be preserved at each interface.

\subsection{Coalgebraic contracts}
We model the contract as a coalgebra:
\[
\gamma:S\to F(S),
\]
where $F$ captures observable behaviors. Authorization guards refine $\gamma$ to an authorized coalgebra. This supports bisimulation arguments: two contract versions are equivalent if they produce the same authorized traces.

\section{Data Availability and Recursive Mitigation}
A significant critique of hash-based signatures is the \emph{signature bloat} (e.g., WOTS+ signatures can exceed 2--4 KB). In a typical L1/L2 environment, posting this as calldata is economically prohibitive. Our framework solves this via \textbf{Proof-Carrying Authorization (PCA)}.

\subsection{Succinctness via Recursion}
Instead of verifying the WOTS+ signature directly in the on-chain Cairo contract, the user (or a specialized prover) executes the verification off-chain. This generates a STARK proof $\pi_{auth}$ which asserts: 
\begin{center}
\emph{"There exists a signature $\sigma$ such that $\Verify(R, M, \sigma) = \texttt{true}$."}
\end{center}
The on-chain contract only verifies $\pi_{auth}$. This collapses the calldata cost from $O(|\sigma|)$ to $O(|\pi_{auth}|)$, where $|\pi_{auth}|$ is logarithmic relative to the execution trace. This move transforms the "ZK-PQC Gap" into a "ZK-Succinctness Advantage."

\subsection{Trace Compression}
By lifting the heavy hash-chain iterations into an off-chain STARK, we bypass the Cairo step limit for a single transaction. This allows the system to support arbitrarily large Merkle trees and robust security parameters without impacting L1 gas costs.

\section{Cryptanalytic Hardening and Parameterization}
To address the critique of experimental reliance on Poseidon, we formalize the \textit{ZK-PQC Parameterization Matrix}.

\subsection{Poseidon Configuration for 128-bit PQ Security}
To ensure 128-bit security against Grover's $\mathcal{A}_Q$, we move beyond standard Cairo-native Poseidon ($t=3$). We specify a **Hardened State** ($t=4$ or $t=6$) to facilitate larger internal entropy.
\begin{center}
\begin{tabular}{|l|c|r|}
\hline
Parameter & Value & Description \\ \hline
$t$ & 6 & Width (state elements) \\
$R_f$ & 8 & Full rounds count \\
$R_P$ & 83 & Partial rounds (security margin) \\
Field & $\F_{251}$ & Cairo Prime Field \\
\hline
\end{tabular}
\end{center}
The selection of $R_P = 83$ partial rounds is derived to ensure that the algebraic degree of the permutation exceeds the $2^{128}$ threshold required for quantum resistance. Assuming $d=5$ for the S-box power map, the accumulated degree $5^{R_P}$ significantly exceeds $2^{128}$, which is a necessary condition to mitigate Grover-assisted speedups and provide a robust security margin against Gröbner basis interpolation attacks in the large prime field $\F_{251}$.
\begin{remark}
This configuration extends the standard $t=3$ parameters used in Cairo execution to a wider $t=6$ state, increasing the security anchor while slightly increasing the AIR constraint cost for each hash step.
\end{remark}

\subsection{Hybrid-Hash Fallback (Agile Hashing)}
Recognizing the experimental nature of Poseidon in signature schemes, our framework implements a \textbf{Hybrid-Hash Architecture}. The Merkle tree and OTS structures can be initialized with a \emph{Hash-Agility Flag}:
\[ \Hash_{eff} = \text{Poseidon}(m) \oplus \text{Truncate}(\text{SHA-256}(m)) \]
\textbf{Refinement Warning:} While SHA-256 provides a standard security anchor, its arithmetization in Cairo (based on bitwise XOR/Rotations) is significantly more expensive than Poseidon. Provers using this hybrid mode should expect recursive verification costs to increase by \textbf{approx. $25$-$40\times$} compared to pure Poseidon paths.

\section{Systems Engineering and Layer 0 Scalability}
The operationalization of OTS-family schemes at Layer 0 poses two significant challenges: \emph{state bloat} from index tracking and \emph{transaction serialization} due to monotonically increasing n-time indices.

\subsection{State Management: Segmented Sparse Bitmaps}
To track spent indices efficiently without linear state growth, we implement a \textbf{Segmented Sparse Bitmap}. Instead of a monolithic bit-array, the contract manages a high-level Merkle root of the "Spent-State." When a signature $(M, \sigma, idx)$ is submitted, the proof must include a "Non-Spent Proof" verified against a Sparse Merkle Tree (SMT). Updating the spent-state involves a logarithmic $O(\log N)$ update to the SMT root, maintaining the on-chain storage footprint at a constant 32 bytes. 

To mitigate the depth of 64 levels required by \texttt{uint64} indices, the state management implements a \textbf{Jellyfish Merkle Tree (JMT)} architecture. By using a depth-optimized structure where internal nodes are only instantiated for active branches, the verification cost in the batch prover scales with the number of spent leaves rather than the theoretical $2^{64}$ maximum. This ensures that the STARK constraint budget is preserved for transaction volume rather than tree traversal.

\subsection{Data Availability: SMT State Reconstruction}
To ensure the \textit{liveness} of the protocol in the event of sequencer equivocation or disappearance, the framework mandates the publication of \textbf{SMT State Diffs} as calldata on the settlement layer. 

\textbf{Payload Structure:} The DA payload consists of a tightly packed vector of \texttt{uint64} indices representing the OTS leaves transitioned from "unspent" to "spent" within the batch. By publishing only the indices rather than the full authorization data, we minimize the L1 footprint.

\textbf{Numerical Scalability Proof:}
Consider a batch of $1,000$ transactions. 
\begin{itemize}
    \item \textbf{Raw PQC Bloom:} $1,000$ WOTS+ signatures ($\sim 3$ KB each) would require $\sim 3$ MB of calldata, exceeding many L2 block limits.
    \item \textbf{SMT Diff Optimization:} With our approach, the DA payload is $1,000 \times 8$ bytes = $8$ KB. 
\end{itemize}
This reduction of **$>375\times$** ensures that even under massive congestion, network observers can reconstruct the SMT state and maintain protocol continuity trustlessly.

\subsection{Concurrency: Index-Buffered Account Abstraction}
To prevent the "Single-Threaded Account" problem critiqued by systems engineers, we propose \textbf{Index-Buffered Authorization}. By leveraging Account Abstraction (AA), the account itself maintains an \emph{Index Window}. Users can sign transactions with any index within a valid window (e.g., $idx \in [base, base + 64]$). This allows the mempool to process multiple independent transactions from the same account in parallel, provided their indices do not collide. The sequencer aggregates these into a single state update, resolving the "spent-flag" collisions off-chain before batch settlement.

  Axiom collision_resistant :

| p_node  : root -> path -> index -> path.

  reconstruct L p = R -> leaf_included L R.

\section{Appendix B: HyperLTL Hyperproperties for Authorization Safety}
\label{app:hyperltl}
Hyperproperties express relations across traces. They are essential when each execution looks fine in isolation but the system fails when comparing multiple executions (replay, equivocation, cross-domain signatures, index reuse across sessions).

Below are representative HyperLTL-style templates. They serve as spec requirements and can be used to guide model checking and differential fuzzing.

\[
\forall \pi_1.\forall \pi_2.\;
\square ((\textsf{Accepted}_{\pi_1} \wedge \textsf{Accepted}_{\pi_2} \wedge
\textsf{Idx}_{\pi_1} = \textsf{Idx}_{\pi_2}) \Rightarrow \pi_1 = \pi_2).
\]
\textbf{Note on Reorgs:} In a branching state model (blockchain), we define a \emph{Fork-Sensitive Operator} $\mathcal{F}$ ensuring that if an index is revealed on fork $A$, it is considered "tainted" on fork $B$ even if $B$ becomes the canonical chain.
\[
\forall \pi_1 \in \text{Fork}_A, \forall \pi_2 \in \text{Fork}_B.\ (\textsf{Rev}(\pi_1, i) \wedge \textsf{Rev}(\pi_2, i)) \rightarrow \textsf{Message}(\pi_1) = \textsf{Message}(\pi_2)
\]
This prevents adversarial equivocation across chain divergences.

\subsection*{H2: Domain separation}
A signature valid in one domain must not be valid in another domain.
\[
\forall \pi_1.\forall \pi_2.\;
(\textsf{SigOk}_{\pi_1} \wedge \textsf{SameSig}_{\pi_1,\pi_2} \wedge
\textsf{Domain}_{\pi_1}\neq \textsf{Domain}_{\pi_2}) \Rightarrow \neg \textsf{SigOk}_{\pi_2}.
\]

\subsection*{H3: Replay protection}
Nonce uniqueness (or monotonicity) is enforced across traces:
\[
\forall \pi_1.\forall \pi_2.\;
(\textsf{Accepted}_{\pi_1}\wedge \textsf{Accepted}_{\pi_2}\wedge
\textsf{Nonce}_{\pi_1}=\textsf{Nonce}_{\pi_2}\wedge
\textsf{Msg}_{\pi_1}=\textsf{Msg}_{\pi_2}) \Rightarrow \pi_1=\pi_2.
\]

\subsection*{Practical note: Trustless Enforceability via Fraud Proofs}
We explicitly pivot from the "offline-only" model check to a \textbf{Trustless Accountability} model. While HyperLTL properties are too complex for real-time L1 verification, they define the formal triggers for \textbf{ZK-Fraud Proofs}. 

\subsection*{Formalization of ZK-Slashing and Punitive Logic}
The relationship between a HyperLTL violation and the contract state is governed by a **ZK-Slashing Predicate**. Let $\mathcal{H}$ be the set of safety hyperproperties. If a sequencer $S$ produces a batch sequence $\tau$ such that $\tau \not\models \mathcal{H}$, any observer can generate an \textit{Existential Fraud Proof} $\Pi_{\mathcal{F}}$.
\begin{equation}
\text{VerifySlashing}(\Pi_{\mathcal{F}}, \tau, S) = \text{true} \Rightarrow \text{State}_{L0}' = \text{Slash}(S.stake, 100\%) \wedge \text{Eject}(S) \wedge \text{Halt}(\tau)
\end{equation}
The mechanism enforces a \textbf{Total Loss} of the sequencer's bonded stake and triggers a \textbf{Consensus Circuit Breaker} to prevent state progression until the equivocation is resolved. This ensures that the cost of an attack always exceeds the potential profit from PQC-key compromise.

\section{Appendix C: AIR Formal Specification Outline (STARK Arithmetization)}
\label{app:air}
This appendix provides a structured outline of AIR constraints for arithmetizing verification. A concrete instantiation depends on the chosen hash (Poseidon/Pedersen) and proof system conventions, but the shape is stable.

\subsection*{Trace structure}
Let the execution trace be a sequence of rows $T[0],\dots,T[N-1]$ over field $\F_p$. Columns include:
\begin{itemize}
\item message transcript columns (domain-separated hash inputs),
\item hash state columns (sponge/permutation states),
\item Merkle path columns (sibling nodes + direction bits),
\item WOTS chain columns (step counters and intermediate hashes),
\item boolean selector columns (enable flags, direction bits).
\end{itemize}

\subsection*{Constraint families}

\textbf{C1: Booleanity.} For any bit column $b(x)$ defined over the evaluation domain $H = \{\omega^i\}_{i=0}^{N-1}$:
\[
P_{\text{bool}}(x) = b(x)(b(x)-1) = 0 \pmod{Z_H(x)}
\]
where $Z_H(x) = x^N - 1$ is the vanishing polynomial over $H$.

\textbf{C2: Multi-Element Hash permutation.} To maintain 128-bit quantum security in a 251-bit field, the hash function $\Hash_{PQ}$ is modeled as a multi-output permutation. Constraints must link the full sponge state across $2 \times 251$-bit segments:
\[
\text{State}_{out}[0,1] = \text{PoseidonPermutation}(\text{State}_{in} \concat \text{Padding})
\]

\textbf{C3: HexTree (Arity-16) Sponge Transition Polynomials.}
Let $S(x)$ be the state column and $I(x)$ the input column. The absorption for arity-16 requires 5 sequential steps per node. For $x \in H \setminus \{\omega^{N-1}\}$:
\begin{equation}
    P_{\text{sponge}}(x) = S(x \cdot \omega) - \text{PoseidonPerm}(S(x) + I(x)) = 0
\end{equation}
Boundary constraints force $S(\omega_0) = \text{Init}(\textsf{DS}, \vec{I}_{node\_start})$ and $x_{\ell+1} = \text{Extract}(S(\omega_{node\_end}))$.
\textbf{Justification of Arity-16 (HexTree) Trade-off:} While increasing arity to 16 increases the constraint width (due to 5 sequential sponge permutations per node), it reduces the \textit{recursive depth} of the tree. In STARK-based recursive proof systems, the "Depth of Recursion" is the primary bottleneck for prover memory and proof-wrapping overhead. By reducing the number of proof steps (recursion levels) by a factor of 4, we minimize the accumulation of FRI errors and improve overall prover liveness, even at the cost of wider polynomial constraints per step.

\textbf{C4: WOTS+ Chain Transition Polynomial.}
For a chain column $Y(x)$ and domain-separated hash $\Hash$, the transition over the active rows $x \in H_{\text{active}}$ is:
\[
P_{\text{chain}}(x) = Y(x \cdot \omega) - \Hash(\textsf{DS} \concat Y(x)) = 0
\]
The polynomial $P_{\text{chain}}(x)$ vanishes on all rows except the terminal chain elements, where boundary constraints link the leaf to the Merkle tree inputs.

\textbf{C4.1: WOTS+ Checksum Arithmetization.}
To prevent existential forgery where an adversary iterates hash chains forward, the AIR must enforce a checksum. The message $M$ is decomposed into a base-$w$ vector $\vec{m} = \{m_1, \dots, m_\ell\}$ using a lookup argument for range checks $0 \leq m_i < w$. The provador must compute the complement sum:
\begin{equation}
    C = \sum_{i=1}^{\ell} (w - 1 - m_i)
\end{equation}
The checksum $C$ is then decomposed into its own base-$w$ elements and assigned to additional verification chains. The total number of chains in the trace is $|M|_w + |C|_w$.

\textbf{C5: Boundary constraints.}
At trace start: initialize transcript and counters.
At trace end: enforce computed root equals committed root $R$ and the final accept flag is $1$ if and only if all constraints passed.

\subsection*{Soundness interface contract}
The AIR spec must align with the Cairo verifier:
\[
\Exec_{\textsf{Cairo}}(M,\sigma)\text{ accepts } \iff
\Exec_{\textsf{AIR}}(M,\sigma)\text{ has a satisfying trace.}
\]
This is a refinement obligation: the implementation must be proven (ideal) or differentially tested (minimum) to match AIR semantics.
